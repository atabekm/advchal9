# Task 24 — Citations, sources and "I don't know"

Every answer has three parts: the answer, the sources it used (source + section + chunk_id)
and quotes copied from those chunks. The code checks the quotes against the chunk text.
Weak context gives "I don't know" plus a clarifying question. Ten mixed control questions
test that every answer has sources and quotes, and that the answer says what the quotes say.

Python 3.13, `uv`. Built on a copy of task 23, `rewrite+rerank` pipeline. Ollama
`nomic-embed-text`, local `bge-reranker-base`, DeepSeek (`deepseek-flash`) for rewriting,
answers, clarifying questions and grading.

## Decisions

| | choice | why |
|---|---|---|
| base | copy task 23 (`indexer/`, `rag/`, `tests/`; `docs/` and `index/` copied, gitignored); default mode `rewrite+rerank` | the best pipeline in task 23 (10/10 expected sources in the context) |
| answer format | DeepSeek JSON mode: `{"status": "answer"\|"unknown", "answer", "citations": [{"ref", "quote"}], "clarification"}` | free text can't be checked; with JSON, missing parts can be detected and retried |
| sources | the model picks only `ref` numbers; the code fills in source, title, section, pages and chunk_id from the `Hit` | the model can't invent a file name or a chunk_id |
| quote check | normalize (PDF hyphenation `-\n`, whitespace, quotes and dashes, case), then `rapidfuzz.fuzz.partial_ratio(quote, chunk) ≥ 90` against the chunk the `ref` points to | PDF extraction and the model's small changes break exact matching; a made-up quote scores far below 90 |
| failed quotes | dropped; if no checked quote is left, the answer becomes "I don't know" | no answer goes out without evidence |
| bad reply | invalid JSON, empty citations on an answer, or an unknown `ref` → one retry with the error spelled out, then "I don't know" | "always returns sources" has to hold even when the model slips |
| "I don't know" — gate 1 (before the LLM) | best rerank score < threshold (task 23's 0.3 for rewrite+rerank) | relevance below the threshold, as the task asks; catches off-topic questions (q09) without an answer call |
| "I don't know" — gate 2 (the model) | the prompt tells it to return `status: unknown` when the passages don't state the answer | task 23 showed near-miss questions score like real answers (0.96), so only reading the passages catches them |
| clarifying question | generated by the LLM. Gate 1: a small call with the question and the titles/sections of the closest chunks (even under the threshold). Gate 2: the `clarification` field of the same reply | it can name what the documents do cover ("did you mean … in TatarTTS?") |
| new judge | **faithfulness**: sees only the answer and the checked quotes; verdict supported / partial / unsupported, and the unsupported claims | the task's "the answer means what the quotes say", which task 23's correctness judge did not test |

## The pipeline

```
question ─▶ rewrite ─▶ search ─▶ RRF ─▶ rerank ─▶ best score < threshold? ──yes──▶ LLM: clarifying question ─▶ I don't know + question
                                                         │ no
                                                         ▼
                              DeepSeek (JSON: status, answer, citations[ref, quote], clarification)
                                                         │
                     parse ─▶ check refs ─▶ fuzzy-match each quote in its chunk ─▶ drop failed quotes
                       │ bad: retry once                                   │
                                                status unknown, or no quote left? ──yes──▶ I don't know + question
                                                                           │ no
                                                                           ▼
                                      answer [n]  +  Sources: [n] source · section · chunk_id  +  Quotes: [n] "…"
```

## Evaluation

Per question, `rag eval` checks:

| check | how |
|---|---|
| **sources present** | answers: ≥ 1 source, each `ref` points to a kept chunk |
| **quotes present** | answers: ≥ 1 quote |
| **quotes verified** | share of quotes that pass the fuzzy match (before they are dropped) |
| **faithful** | faithfulness judge: supported / partial / unsupported |
| **correct** | task 23's judge against `expect` (kept so we see the format didn't cost quality) |
| **I don't know right** | should-refuse → refused with a clarifying question; answerable → not refused |
| **expected source cited** | a cited chunk matches `sources` in questions.json |

For contrast, a `legacy` mode runs task 23's free-text prompt, and its `[n]` markers are
scored the same way: how often a free-text answer leaves out a citation, and whether the
JSON format changes correctness. EVAL.md: summary table, a written reading, and each
answer with its sources, quotes and verdicts.

## Stages

One branch, `task24/citations`, one commit per stage, one PR at the end (as in tasks 22
and 23).

1. **copy + structured answer**: copy task 23, the JSON prompt, `cited.py` (parse, ref
   check, sources filled from hits), the retry, ask/chat output with Sources and Quotes,
   `--json`. Tests with a mocked LLM (good reply, bad JSON, unknown ref, missing citations).
2. **quote verification**: `rapidfuzz`, `verify.py`, failed quotes dropped, no quote → I
   don't know, `--show-context` shows the scores. Tests on real chunk text (hyphenation,
   changed whitespace, a paraphrase that must fail).
3. **"I don't know" + clarification**: gate 1 with `clarify.py`, gate 2 from
   `status: unknown`, both returning a clarifying question; the 10 questions, including
   the new ambiguous one. Tests for both gates.
4. **evaluation**: faithfulness judge, the new checks, `legacy` vs `cited`, a full run,
   EVAL.md with the reading, README.

## What the build changed

- **Quotes that fail the check trigger the retry too**, not only format errors. The model gets
  the failed quotes with their match scores; only after the retry are they dropped.
- **One gap in quote matching.** A real quote scored 81 because a page break (footnote URL and
  running header) sits inside the sentence in the chunk. A quote may now match as head + tail
  (≥ 4 words each, in order); a changed tail still fails.
- **The prompt asks for a quote per fact**, and to drop what cannot be quoted. With only "every
  [n] needs a quote", 3 of 7 answers were fully supported by their quotes; with it, 5–6.
- **An ambiguity rule in the prompt.** At temperature 0, q16 ("What did the evaluation show?")
  went from "I don't know" to an answer about one of the two evaluations between runs; the rule
  makes the model name both and ask which one.
- **Clarifications are tidied**: a repeated "I don't know:" and `[n]` markers (the user doesn't
  see the passages) are removed from both gates' text.
- **A new question kind, `ambiguous`**, judged like unanswerable: "I don't know" is correct.
- **`--style legacy`** (and `legacy:MODE` in `rag eval`) instead of a separate mode, so both
  styles share one retrieval in the eval.
